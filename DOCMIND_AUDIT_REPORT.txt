1. EXECUTIVE STATUS

- PDF text extraction and table extraction.

2. ARCHITECTURE
===============

2.1 UPLOAD PIPELINE
-------------------

Request entry point:
- File: backend/routers/upload.py
- Function: upload_documents()
- Endpoint: POST /api/upload
- Authentication: Depends(get_current_user)
- Upload processing: FastAPI BackgroundTasks

Flow:

POST /api/upload
  -> get_current_user()
  -> validate_file()
  -> sanitize_filename()
  -> write storage/temp/{doc_id}_{filename}
  -> insert documents database row
  -> BackgroundTasks.add_task(_process_document)
       -> parse_document()
       -> classify_document()
       -> index_document()
       -> mark job complete

2.2 FILE VALIDATION
-------------------

File: backend/core/security.py

Function: validate_file(file)

Implemented checks:
- Allowed extensions: .pdf, .png, .jpg, .jpeg, .tiff.
- MIME type validation.
- File size limit from MAX_FILE_SIZE_MB, default 20 MB.
- Magic-byte validation.
- Filename sanitization through sanitize_filename().
- Path traversal protection through basename and character filtering.

Important defect:
- PNG, JPEG, and TIFF files are accepted by validation.
- backend/services/parser.py only handles .pdf.
- parse_document() returns [] for other file types.
- Such files can be marked complete without indexed content.

2.3 TEXT EXTRACTION
-------------------

File: backend/services/parser.py

Functions:
- parse_document()
- _parse_pdf()

Library:
- pdfplumber

Behavior:
- Opens each PDF with pdfplumber.
- Calls plumber_page.extract_text() for every page.
- Stores page number, text, image filename, table information, and image path.

2.4 TABLE EXTRACTION
--------------------

Library:
- pdfplumber

Function:
- plumber_page.extract_tables()

Behavior:
- Extracted tables are converted to text by _table_to_text().
- Table text is appended to normal page text before chunking.
- Structured tables remain in the temporary page object.
- Structured table data is not separately stored in Chroma.

2.5 OCR FALLBACK
----------------

File: backend/services/parser.py

Function:
- _try_import_ocr()
- OCR call inside _parse_pdf()

Libraries:
- pdf2image
- pytesseract
- Poppler system binary
- Tesseract system binary

Trigger:
- OCR runs when extracted page text has fewer than 20 characters.

Behavior:
- PDF pages are converted to JPEG images.
- Images use 100 DPI for PDFs up to 30 pages and 72 DPI for larger PDFs.
- OCR input is resized to half dimensions.
- pytesseract.image_to_string() is called.
- Page thumbnails are saved under IMAGES_PATH.

Deployment concern:
- render.yaml sets TESSERACT_CMD=tesseract.
- Render build.sh installs Python packages only.
- No Tesseract or Poppler installation is configured in the repository.

2.6 CLASSIFICATION
------------------

File: backend/services/classifier.py

Function:
- classify_document()

Provider:
- Groq

Exact model:
- qwen/qwen3.6-27b

API call:
- client.chat.completions.create()

Configuration:
- temperature=0.1
- max_tokens=800
- reasoning_format=hidden

Input:
- First five pages only.
- At most 1,000 characters from each page.

Output:
- JSON classification containing document type, topic, sensitivity, entities, characteristics, and summary.

Failure behavior:
- Returns a fallback classification with document_type=other and sensitivity_level=internal.

2.7 CHUNKING
------------

File: backend/services/embedder.py

Function:
- chunk_text()

Configuration:
- CHUNK_SIZE=500 characters.
- CHUNK_OVERLAP=50 characters.

Behavior:
- Character-based chunks, not token-based.
- Empty chunks are discarded.
- IDs use {doc_id}_p{page_number}_c{chunk_index}.

2.8 EMBEDDINGS
--------------

File: backend/services/embeddings.py

Provider:
- Google GenAI

API:
- client.models.embed_content()

Exact model:
- models/gemini-embedding-001

Functions:
- get_embedding()
- get_embeddings()

Behavior:
- Individual query embeddings use get_embedding().
- Bulk indexing uses batches of 10.
- Rate-limit failures retry up to six attempts.
- Backoff is 30, 60, 90, then 120 seconds.

Documentation mismatch:
- README claims Gemini text-embedding-004.
- Current code uses models/gemini-embedding-001.

2.9 STORAGE
-----------

File: backend/services/embedder.py

Database:
- ChromaDB PersistentClient.

Collection:
- documents

Distance:
- cosine via metadata hnsw:space=cosine

Storage path:
- CHROMA_PATH, default ./storage/chroma_db

Metadata stored per chunk:
- doc_id
- user_id
- doc_name
- page_number
- image_filename
- sensitivity_level
- document_type
- chunk_index

PDF storage:
- Completed PDFs are moved to storage/pdfs/{doc_id}.pdf.
- Non-PDF temporary files are deleted after processing.


3. CHAT AND QUERY PIPELINE

3.1 STANDARD CHAT
-----------------

File: backend/routers/chat.py

Endpoint:
- POST /api/chat

Flow:

POST /api/chat
  -> get_current_user()
  -> _require_owned_document()
  -> answer_query()
       -> search()
       -> relevance filtering
       -> prompt construction
       -> Groq chat completion
       -> citation extraction
       -> citation marker replacement
  -> persist user and assistant messages

3.2 RETRIEVAL
-------------

File: backend/services/embedder.py

Function:
- search()

Vector retrieval:
1. Generate a Gemini query embedding.
2. Query Chroma.
3. Apply metadata filter user_id == current user.
4. If supplied, also apply doc_id == requested document.
5. Convert Chroma distance into relevance_score = 1 - distance.

Hybrid retrieval:
- Enabled only when HYBRID_SEARCH_ENABLED=true.
- BM25 index is built from Chroma documents.
- BM25 filtering applies user_id and optional doc_id.
- Chroma and BM25 rankings are fused using reciprocal rank fusion.

3.3 RERANKING
-------------

There is no model-based reranker.

The repository has:
- Chroma vector ranking.
- Optional BM25 keyword ranking.
- Reciprocal rank fusion.

RRF is ranking fusion, not semantic reranking.

3.5 CITATIONS
-------------

File: backend/services/rag.py

Behavior:
- Detects [SOURCE N] markers in the model response.
- Creates citation records containing:
  - doc_name
  - page_number
  - image_filename
  - doc_id
  - excerpt
- Replaces markers with [filename, p.N].

If the model omits markers:
- Standard RAG returns no citation objects.
- Agentic RAG has a separate fallback reference list.

4. AGENTIC LAYER
=================

Status: IMPLEMENTED, not merely a stub.

File:
- backend/services/agentic_rag.py

Library:
- LangGraph StateGraph

Endpoint:
- POST /api/chat/agentic

Graph:

START
  -> planner
  -> retriever
  -> critic
  -> conditional route
       critic -> retriever when evidence is insufficient
       critic -> synthesizer when evidence is sufficient
  -> END

Nodes:

Planner:
- Groq qwen/qwen3.6-27b.
- Classifies a question as simple or complex.
- Produces one question for simple queries.
- Produces 2-4 subquestions for complex queries.
- Falls back to the original question on invalid output.

Retriever:
- Runs the existing search() function for each subquestion.
- Preserves user_id and optional doc_id filters.
- Executes searches concurrently with asyncio.gather().

Critic:
- Groq qwen/qwen3.6-27b.
- Returns sufficient or insufficient.
- Can produce a rewritten query.
- Allows up to two retrieval retries per subquestion.

Synthesizer:
- Groq qwen/qwen3.6-27b.
- Synthesizes only evidence marked sufficient.
- Filters unsafe-looking output.
- Converts [SOURCE N] into readable citations.
- Adds a references list if the model omits explicit source markers.

State includes:
- original_question
- user_id
- doc_id
- conversation_history
- sub_questions
- retrieved_chunks
- critic_verdicts
- retry_counts
- retrieval_queries
- final_answer
- citations
- has_answer

Documentation mismatch:
- Older comments describe this as a future or phase-1 stub.
- Current code contains the complete planner/retriever/critic/synthesizer flow.

6. AUTHENTICATION AND ISOLATION
===============================

Authentication implementation:
- JWT access tokens.
- HS256 signing.
- Configurable expiration, default 60 minutes.
- bcrypt password hashing.
- User lookup from PostgreSQL on every authenticated request.

Files:
- backend/core/auth.py
- backend/routers/auth.py

Chat ownership:
- Both /api/chat and /api/chat/agentic call _require_owned_document().
- Ownership SQL checks doc_id and user_id.
- Retrieval independently applies user_id and optional doc_id metadata filters.

Chroma isolation:
- Each current chunk stores user_id and doc_id.
- Chroma vector search filters by user_id and optional doc_id.
- BM25 search also filters by user_id and optional doc_id.
- Focused tests cover cross-user BM25 isolation.

Confirmed ownership gap:

Page-image endpoint:
- Endpoint: GET /api/page-image/{image_filename}
- Requires authentication.
- Validates characters and real path.
- Does NOT verify that the image belongs to a document owned by the caller.
- Image names include doc_id, so a user who knows or guesses another UUID may request another user’s page image.

Chat history:
- GET /api/chat/history/{doc_id} filters by user_id and doc_id.
- It does not explicitly verify document ownership.
- Foreign IDs return empty history rather than an access error.

Legacy Chroma data:
- scripts/backfill_chroma_user_metadata.py exists because older records may lack user_id.
- Current search excludes chunks without matching user_id.
- Older documents may therefore be invisible until backfilled.

- Agentic unsafe-output filtering.

PARTIAL OR RISKY:

Rate-limit configuration:
- RATE_LIMIT_PER_MINUTE is read from config.
- main.py hardcodes default_limits=["30/minute"].
- Changing RATE_LIMIT_PER_MINUTE has no effect.

Rate-limit distribution:
- SlowAPI is process-local/in-memory.
- It is not a distributed limiter for multiple workers or instances.

Background processing:
- FastAPI BackgroundTasks is not a durable queue.
- Processing can be lost during restart or deployment.

Prompt injection:
- Suspicious phrases are logged.
- Suspicious content remains searchable.
- Protection depends on prompt framing and model compliance.

Voice input:
- audio_base64 has no explicit request-size cap.

JWT secret:
- Missing JWT_SECRET_KEY silently defaults to changeme.
- Startup does not reject the default secret.

MISSING:
- Virus scanning.
- Encryption at rest.
- Audit logging.
- Durable job queue.
- Hosted/distributed vector storage.
- Document-level ACLs beyond owner-only access.
- Database migrations/schema in the repository.

STALE DOCUMENTATION CLAIMS:
- README claims LLaMA-3.3 70B Versatile; code uses qwen/qwen3.6-27b.
- README claims Gemini text-embedding-004; code uses models/gemini-embedding-001.
